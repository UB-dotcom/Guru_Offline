2. React Native & TypeScript Modules (Mobile Frontend)

The mobile application frontend utilizes lightweight, battle-tested npm modules chosen specifically for low memory footprint on entry-level Android devices:

react (18.2.0) & react-native (0.74.1) Core Framework
Provides the declarative component model (functional components, hooks: useState, useEffect, useCallback, useMemo) and native mobile primitives (View, Text, ScrollView, FlatList, TouchableOpacity, StyleSheet).
Role: Core application UI shell, responsive card lists, streaming chat bubbles, and modal dialogues.
zustand (4.5.2) State Management
Minimalist reactive state management library (<2 KB bundle size). Consumes significantly less memory than Redux or MobX and eliminates unnecessary component re-renders on weak CPU cores.
Powers 5 core stores: authStore, moduleStore, profileStore, progressStore, and tutorStore.
@react-navigation/native, stack, bottom-tabs Routing & Navigation
Native screen transition coordinator. Manages stack flows (Onboarding, Authentication, Module Details) and persistent bottom navigation tabs (Home, Modules, Tutor, Practice, Progress, Profile).
Configured in src/navigation/RootNavigator.tsx and MainNavigator.tsx.
react-native-screens (3.31.1) & react-native-safe-area-context (4.10.1) Native Views & Insets
Replaces bloated JavaScript view hierarchies with native Android Fragments / ViewGroups, freeing critical heap memory. Handles device notches and dynamic status-bar insets cleanly.
Essential for preventing Out-Of-Memory (OOM) crashes on 2 GB RAM budget devices.
typescript (5.0.4) & @types/* Static Type Safety
Enforces strict contracts across student profiles, curriculum schemas, quiz data models, and API interfaces. Guarantees compile-time validation across 75 source files.
Strict models in src/types/: student.ts, curriculum.ts, tutor.ts, quiz.ts, module.ts.

3. Python Backend & AI Engine Modules (OfflineTutorAI)

The Python engine in backend/OfflineTutorAI is a modular, zero-dependency offline AI framework designed to run locally on the device or companion local micro-server:

sqlite3 & SQLite FTS5 (Full-Text Search) Built-in Python Module / SQLite 3.x
Embedded database requiring zero external server process. The FTS5 extension creates virtual inverted indices over chapter text, enabling probabilistic BM25 relevance retrieval in < 3 milliseconds.
Powering: curriculum.db, sqlite_retriever.py, and index_manager.py.
llama_cpp (llama-cpp-python) GGUF Inference Engine Binding
Bindings for llama.cpp, the C/C++ engine for executing quantized GGUF models (INT4 Q4_K_M, INT8) directly on CPU cores without requiring heavy PyTorch, TorchScript, or GPU drivers.
Integrated in ai/local_llm/llama_cpp_engine.py for on-device GGUF execution.
fitz (PyMuPDF) & pypdf Textbook Ingestion
C-accelerated PDF parsers that process textbook pages, extract raw text, identify chapter sections, isolate mathematical equations, and prepare cleaned text for chunking.
Integrated in scripts/pdf_extractor.py and admin/upload/pdf_uploader.py.
http.server (HTTPServer, BaseHTTPRequestHandler) Zero-Dependency Loopback Bridge
Zero-dependency HTTP server implemented in backend/local_server.py. Binds to 127.0.0.1:8080 (or 10.0.2.2:8080 for Android emulator) to bridge the React Native UI to the local AI engine.
REST endpoints: POST /ask_tutor, GET /health, GET /api/curricula/published.
